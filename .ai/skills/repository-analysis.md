# Skill — Repository Analysis

## Quando usar

Antes de qualquer alteração ou conclusão que dependa do conteúdo do repositório.

## Procedimento

1. Defina o objetivo exato da tarefa.
2. Liste arquivos e módulos potencialmente envolvidos.
3. Leia os arquivos primários antes de inferir comportamento.
4. Identifique API pública e consumidores.
5. Localize testes relacionados.
6. Localize documentação específica do domínio.
7. Registre comportamento a preservar.
8. Separe alterações autorizadas das proibidas.
9. Em bugs iterativos, consolide tentativas anteriores e respectivos resultados antes de formular nova hipótese.
10. Defina validações possíveis.
11. Defina o artefato final esperado.

## Saída mínima

```text
Objetivo:
Arquivos fonte:
Contratos afetados:
Comportamento a preservar:
Alterações autorizadas:
Alterações proibidas:
Tentativas anteriores relevantes:
Validações:
Entrega:
```

Se algo essencial não puder ser confirmado, use `Não confirmado.` em vez de preencher por suposição.
